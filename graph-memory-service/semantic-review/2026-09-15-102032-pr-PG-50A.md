# Consolidation-cut reject-fix recovery and transport contract

The PG-50A fixes add a flat Error-code contract, durable cut-state recovery, signed cut notifications, and a documented persistence-after-response model. The Error enum covers the codes the cut paths emit, but the individual OpenAPI operations do not declare several transport and infrastructure responses that those paths can return. Recovery has two integrity gaps: a corrupt idempotency index can make a caller receive a different tenant's job, and the persisted service/freezer pair can be captured at two different logical moments. The optional notifier also turns a sink outage into a nil-pointer panic when constructed through its public no-logger constructor. Watch for: **confirmed** cross-tenant job disclosure from an accepted corrupted snapshot; **confirmed** notification sink failures can fail requests; **confirmed** a crash can retain a freezer ledger entry without its corresponding cut job.

**Verdict**: NEEDS_CHANGES

## High-level view

The cut error-code enumeration was extended consistently, but OpenAPI still advertises only a subset of the HTTP outcomes the route-level transport gate and handlers emit. Clients generated from this contract cannot model ordinary malformed-request, authentication, or infrastructure failures for most cut operations.

`Service.Restore` validates that an idempotency target exists, but not that the stored request, composite key, and target job describe the same tenant and room. The normal replay path trusts that relationship and returns the indexed job before applying the usual `Get` tenant check.

The notifier preserves the narrow signed payload and stable replay event ID, but its default public constructor intentionally supplies no logger while the sink-error path assumes one. A notification failure therefore ceases to be non-authoritative in that supported construction.

The persistence model explicitly permits acknowledgement before durability, but it calls the service and freezer snapshots independently before obtaining the write mutex. Concurrent cut requests can write a syntactically atomic file containing a newer freezer ledger and an older job set.

## OpenAPI response inventory diverges from cut-path emissions

**Confirmed, medium — `openapi/consolidation-cuts.yaml:47-58,68-75,85-94`; `internal/httpapi/handler.go:130-171,315-351`; `internal/httpapi/consolidation_cuts.go:681-903`.** The newly expanded `Error.code` enum contains the static transport and cut-domain codes, but the operation response inventories do not describe all outcomes that the same routes emit. For example, every cut route can return `401 UNAUTHORIZED`; body-bearing routes return `400 INVALID_REQUEST` or `INVALID_JSON`; path validation returns `400 PAYLOAD_VALIDATION_FAILED`; read and mutation handlers return `500 INFRASTRUCTURE_FAILURE`; and cancel/rediagnose can return `409 ROOM_EPOCH_STALE`. GET declares only 200/404, while cancel and rediagnose declare only 202/404. The 409 create response is also described specifically as an idempotency conflict despite the handler emitting `ROOM_EPOCH_STALE` from that route.

Add reusable OpenAPI responses for the transport and infrastructure envelope and reference them on every applicable operation, with a separate stale-view 409 description where appropriate. Extend the contract test beyond route enumeration to exercise the declared error status/code inventory.

## Restore trusts a forged idempotency relationship

**Confirmed, high — `internal/consolidationcut/service.go:471-476,1431-1480`; `internal/consolidationcut/snapshot_restore_test.go:54-110`.** `Restore` confirms only that each idempotency entry points to an existing job and has some stored request. It does not verify that the map key equals `idempotencyKey(request.TenantID, request.RoomID, request.TriggerSource, request.IdempotencyKey)`, nor that the target job belongs to that request's tenant and room. On a subsequent trigger, `Trigger` derives the caller's key, accepts a matching stored request, and returns `s.jobs[existing]` directly. An image whose tenant-A key/request points at tenant-B's existing job is accepted at boot and exposes the tenant-B job in tenant-A's create response; the normal `Get` tenant fence is bypassed.

Validate the key-to-request derivation, target job identity, and target manifest identity before installing restored maps. Add a negative test that creates two tenant jobs, rewires one idempotency entry to the other, and asserts both restore failure and preservation of the pre-existing in-memory service.

## Sink errors panic through the supported no-logger notifier

**Confirmed, high — `internal/httpapi/consolidation_cuts.go:434-435,448-469`; `internal/httpapi/consolidation_cut_contract_test.go:506-535`.** `NewCutEventNotifier` delegates with `logger == nil`, which its own documentation presents as a valid construction. If its enabled sink returns an error, `Notify` invokes `n.logger.Log(...)` unconditionally. This nil dereference converts an optional notification append failure into a request panic, contradicting the notifier's non-authoritative delivery contract. The current sink-error test exercises only `NewCutEventNotifierWithLogger`, so it misses the public constructor path.

Guard the log call when no operational logger was supplied, or substitute a no-op logger at construction. Add the failing-sink test through `NewCutEventNotifier` and assert that `Notify` returns normally while authoritative HTTP state remains unchanged.

## Atomic file publication captures a non-atomic cut composition

**Confirmed, high — `cmd/server/main.go:370-421,445-466`; `internal/httpapi/consolidation_cuts.go:748-756`.** `persistCutState` calls `service.Snapshot()` and then `freezer.Snapshot()` before acquiring `persistMu`; neither snapshot shares a lock with cut mutation. A concurrent trigger can complete between those calls: the persisted service image omits cut B while the freezer image includes B's newly recorded sealed segments. If that mixed image is the last one published before a crash, restart restores no B job or idempotency record but retains B's threshold exclusion, so later threshold cuts silently skip evidence that has no authoritative cut record. The rename prevents torn bytes, not this cross-component logical tear.

Move both snapshots and the mutation that records the freezer ledger under a shared composition coordinator (or persist one service-owned aggregate state) so the pair is linearizable. Add an interleaving test that blocks between the two captures, completes a second trigger, restarts from the first write, and verifies that neither component contains the second cut alone.
